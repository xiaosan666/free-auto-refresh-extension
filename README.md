# 定时刷新 & 自动点击（Chrome 扩展）

一个零依赖的 Manifest V3 扩展：点击扩展图标，在同一个弹窗里配置**定时刷新页面**与**定时自动点击页面元素**，扩展图标上实时显示倒计时。

- 配置按**域名**生效（忽略 `www.` 前缀），同域名下已打开的和后续新开的标签页都会生效，每个标签页独立倒计时。
- 图标 badge 显示剩余时间：剩余 > 1 分钟显示 `5M / 4M / 3M`，剩余 ≤ 1 分钟显示 `59S / 58S / 57S`。

完整需求见 [REQUIREMENTS.md](./REQUIREMENTS.md)。

---

## 1. 安装与调试

1. 打开 `chrome://extensions/`，右上角开启**开发者模式**。
2. 点击**加载已解压的扩展程序**，选择本目录（`free-auto-refresh-extension`）。
3. 建议把扩展图标**固定**到工具栏，方便点击打开弹窗。
4. 修改代码后，回到 `chrome://extensions/` 点击该扩展卡片上的**刷新**按钮即可生效；
   若改动了 `manifest.json`，需要重新加载扩展。
5. 调试：
   - 弹窗：右键弹窗内容 → 检查（或直接右键扩展图标 → 检查弹出内容）。
   - 后台 Service Worker：扩展卡片上的 **Service Worker** 链接可打开 DevTools。

> 无需 Node、无需构建工具，直接用 Chrome 加载目录即可运行。

## 2. 使用说明

### 定时刷新

| 操作 | 行为 |
| --- | --- |
| 点击 `1M / 5M / 10M / 15M / 60M` | 立即生效并关闭弹窗 |
| 输入秒数 → 点「启用」 | 生效并关闭弹窗；输入 < 60 会自动重置为 60 秒并提示 |

倒计时归零时刷新页面；同一域名内地址变化（如 `/a` → `/b`）会**重新开始计时**，刷新功能继续生效。

### 自动定时点击

| 操作 | 行为 |
| --- | --- |
| 填写元素选择器（如 `#submit`、`.btn-next`） | 支持任意 `document.querySelector` 可用的选择器 |
| 填写「第几个」 | 选择器命中多个元素时指定点哪一个：`3` = 第 3 个，`last` = 最后一个，留空 = 第 1 个 |
| 点击 `1M / 4M / 9M / 59M` | 立即生效并关闭弹窗 |
| 输入秒数 → 点「启用」 | 生效并关闭弹窗（最小 1 秒，上限 86400 秒） |

- 可**单独启用**点击，不需要先启用刷新。
- 两者同时启用时，点击周期必须**小于**刷新周期，否则会给出提示且不启用。
- 找不到匹配元素时不会中断倒计时，只在弹窗底部提示「未找到匹配元素，请检查选择器」。
- 序号超出匹配数量时（例如只匹配到 2 个却填 `5`）同样只提示、不中断，提示文案为「只匹配到 2 个元素，序号 5 超出范围」。
- 不想用序号时，也可以直接写更精确的选择器，如 `.list .item:last-child`、`.btn:nth-of-type(2)`、`[data-id="123"]`。
- 再次打开弹窗可以看到剩余倒计时，并可分别点「停止」停用对应功能（图标 badge 同时清除）。

> 启用后弹窗会自动关闭，因此"刷新 + 点击"组合使用需要分两次打开弹窗配置，顺序不限。

## 4. 实现要点

- **时间戳驱动**：只持久化"下次触发时间戳 `nextAt`"，剩余时间由 `nextAt - Date.now()` 推导；后台 Service Worker 被系统回收后恢复即可继续准确倒计时。
- **秒级滴答 + 告警兜底**：SW 内 `setInterval(1000)` 驱动 badge 与动作触发；`chrome.alarms` 30 秒心跳在 SW 被回收后唤醒并重建滴答器。
- **防重复触发**：到点后先把 `nextAt` 推进一个周期再执行动作。
- **切换时间即重新计时**：运行时记录「本次倒计时所使用的周期 / 选择器」，用户切换快捷项或修改自定义秒数后，所有相关标签页立即按新周期重新开始计算。
- **倒计时自绘图标**：原生 badge 在 `60M` 这类 3 字符文案时会折行、且无法控制内边距与字号；这里用 `OffscreenCanvas` 绘成 imageData 交给 `chrome.action.setIcon`，字号按可用宽度自动收敛，保证始终单行；自绘不可用时自动退回原生 badge（淡蓝底 + 深蓝字）。
  两种可选风格（`src/shared/constants.js` 的 `BADGE_STYLE`，改完重载扩展即可）：
  - `solid`（默认）：**纯色倒计时牌** —— 整块蓝底圆角色块，数字独占一行（约 0.75 倍边长）、单位字母 `M/S` 小字排在其下方，数字最大最醒目，代价是看不到原图标。
  - `overlay`：在启用态图标底部叠加淡蓝胶囊（保留图标本体，字号相对小）。
- **点击注入**：`chrome.scripting.executeScript({ func, args })`，注入函数自包含（不引用外部作用域）；无需常驻 content script，页面刷新后下一周期重新注入。
- **状态持久化**：`chrome.storage.local` 存 `domainConfigs`（域名配置）与 `tabRuntimes`（标签页运行时），不依赖全局变量。

## 5. 权限说明

| 权限 | 用途 |
| --- | --- |
| `tabs` | 读取标签页 URL 以判定所属域名，并在倒计时结束时执行 `chrome.tabs.reload` 刷新页面 |
| `scripting` | 向页面注入并执行点击逻辑，实现"定时自动点击指定元素" |
| `storage` | 在本机保存域名配置与倒计时状态，关闭浏览器后仍保留 |
| `alarms` | Service Worker 被系统回收后定时唤醒，保证倒计时持续可靠 |
| `host_permissions: <all_urls>` | 扩展需对**用户主动配置的任意网站**执行刷新与点击，无法预先限定域名 |

**隐私**：扩展不联网、不采集、不上传任何数据，所有配置仅保存在本机 `chrome.storage.local`。

## 7. 常见问题

**Q：为什么 badge 偶尔停住不动？**
A：后台 Service Worker 空闲约 30 秒会被系统回收，此时由 alarms 心跳（最长 30 秒）唤醒并恢复滴答。刷新动作本身由持久化时间戳保证不会丢失。

**Q：为什么点击后页面没反应？**
A：确认选择器能被 `document.querySelector` 命中（可先在目标页面的 DevTools Console 里执行 `document.querySelector('你的选择器')` 验证）；若元素在 iframe 内则无法命中。

**Q：设置了 60 分钟，中途关掉浏览器还生效吗？**
A：域名配置会保留；浏览器重启后标签页恢复时重新开始倒计时。
